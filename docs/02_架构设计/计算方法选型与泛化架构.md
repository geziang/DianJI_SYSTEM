# 计算方法选型与泛化架构

> 文档定位：给"同一算法层、不同算力芯片"的实现选型立规矩——算法层定义"算什么"，芯片档位决定"怎么算"，本文回答两者如何解耦、如何随芯片升级、以及何时该停止软件优化改写"换硬件"结论。
> 核心观点：解耦靠三件套（分层免改、双编译、实现分支规格）；"实事求是"= 先榨干软件，再干净地写换硬件结论（附规格与判据），既不拖泥带水也不提前放弃。
> 当前参考平台：STM32F103C8T6（Cortex-M3 无 FPU）+ DengFOC V3P + 2804 PMSM + MT6701。
> 状态：已对齐（初版 2026-09-16；上游：ARC-01/ARC-02；纪律叙事见调试日志经验14；S3 实现分支先例见 08 交接 §5.4）。

---

## 1. 问题定义

本项目从第一天就定位为**泛化性系统**（ARC-01）：沉淀的是电机控制的对象模型、安全边界、标定与验证方法，当前硬件只是第一套适配实例。于是有一类问题会反复出现：

> 同一个算法（FOC 电流环、S3 电感辨识、速度估计……），落在算力光谱的不同位置——M0/M3 无 FPU → M4F/M7 单精度 FPU → G4/H7 强外设多核——**实现方式应当怎么变？边界在哪？**

这不是"优化技巧"问题，是架构问题：如果"怎么算"的决策散落在代码各处、没有制度载体，每次换芯片就是一次全量重审；反之若有载体，换芯片就是"按分支落地 + 回归验证"。

## 2. 三个制度载体（机制层）

本仓库已有三件套，使芯片相关决策**可定位、可测试、可迁移**：

| 载体 | 内容 | 实例 |
| --- | --- | --- |
| **分层免改** | 算法/流程层零 HAL（`foc_*`/`calib_*` 纯函数），芯片差异全部收在板级与驱动两层；换芯片按 README §9 五步只动两层 | 全部标定/控制算法；F103→F4 适配指南 |
| **双编译（决策 D6）** | 判据与估计器是 PC/MCU 同源的纯 C——先在 PC 上对数据/仿真验算，再上板 | `resistance_learning.c`、`calib_sequence.c`、`speed_estimate.c`（tests/pc/ 单测族） |
| **实现分支规格** | 同一算法在规格层按芯片写实现注记，迁移时按分支落地，算法语义不变 | 08 交接 §5.4：F4/G4 直接 `logf`；C8T6 复跑则 32 点 ln(y) 查表+线性插值、不链 libm |

三件套的分工：**分层**保证"算什么"不动，**双编译**保证"算得对不对"离线可验，**实现分支**保证"怎么算"的芯片差异被规格显式管理而不是散在代码里。

## 3. 选型清单（按芯片能力分档）

| 档位 | 代表 | 默认武器（本项目已验证） | 该档解锁的方法升级 | 仍不该做 |
| --- | --- | --- | --- | --- |
| **无 FPU** | M0/M3（C8T6 现役） | 查表+插值（trig 表 / ln 表）、乘倒数、预算量外提（prepare/derive 时间尺度分层）、惰性开根、差分递推、定点 Q15/Q31 | CMSIS-DSP 软件库仍可用 | ISR 内任何超越函数/浮点除法；相信"再优化一轮就能上 20kHz"（实测 >200% CPU，已存档） |
| **单精度 FPU** | M4F/M7（F411/G431，推荐迁移目标） | 上述全部 + 慢路径超越函数放开（`logf`/`sqrtf` 无压力）；ISR 内浮点降到周期级 | 20kHz 电流环；S3 采样栅格 100µs→25~50µs、健康窗 2 拍→8 拍、自适应选点有的放矢；编码器欠流说谎的 20kHz 判决实验可执行 | ISR 内仍需预算分层与调用纪律；阻塞遥测/轮询仍要治理（FPU 不治阻塞） |
| **强外设/多核** | G4（CORDIC/HRTIM）、H7、双核 | 硬件三角/开方（CORDIC）、高精度 PWM、DMA 全链 | 编码器 ISR 内连续出角（消 1ms 台阶叉耦）；三环并行；VESC 式 HFI+双 bin DFT 辨识进入门様认证 | 不因算力富余放弃测量纪律——窄带/零参考/噪声地板锚定与芯片无关，仍然有效 |

用法说明：向下兼容（新档位继承旧档全部武器）；"仍不该做"一列与武器同样重要——它是每档的边界标桩，防止把算力富余误当测量质量的替代品。

## 4. 软件优化的边界（何时写"换硬件"结论）

**三个硬指标**（越线即触发"停止优化"评估）：

1. **CPU 实测占比**：本平台 10kHz ISR 85-95%、20kHz >200%（上板实锤）；
2. **ROM 余量**：测试 target 1136B——装不下的改造等于不存在；
3. **实验存档**：12 项软件侧排除全记录（08 交接 §4）——已被证伪的路不再重走。

**判定阶梯**（与经验14 纪律四条同构）：测量 → 热点 → 算法近似（函数层） → 调用方式（DMA/中断/批量化） → 编译器选项 → **仍不达，则写换硬件结论**。注意最后一格不是失败：结论必须附三样东西——缺口定量（差多少 CPU/ROM/采样率）、目标档位（§3 清单）、随迁移实施的事项清单与判据（§5.4 先例）。

**三个已判例**：① 20kHz 电流环 → 判换 FPU（缺口：CPU >200% vs 100%；目标：F411/G431）；② 编码器欠流说谎 → 判硬件级、软件到"遏制"为止（经验13：12 项排除 + 九层防御是边界内全部）；③ 三环全闭环预算合计 >100%（08 交接 §5.2）→ 判换芯片而非裁功能。

## 6. 一句话带走

**算法层定义"算什么"，芯片档位决定"怎么算"；分层+双编译+实现分支三件套让"怎么算"可以随芯片升级而不惊动"算什么"——而知道何时停止优化、干净地写出"换硬件"的结论与规格，是同一套实事求是的两半。**
