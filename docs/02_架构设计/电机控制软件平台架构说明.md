# 电机控制软件平台架构说明

> 文档定位：定义本项目真正要沉淀的软件对象模型、硬件适配边界和迁移条件。  
> 核心观点：本项目不是某块 MCU、某块功率板、某个电机的专用程序，而是一套面向 BLDC/PMSM 控制的软件平台。  
> 当前参考平台：STM32F103C8T6 + DengFOC V3P/V3Pro + 2804 电机 + MT6701，仅作为第一套适配实例。

---

## 1. 平台定位

本项目的软件资产应被定义为：

**面向 ADC 电流采样、三相 PWM/SVPWM 输出、无刷电机驱动和分阶段验证的电机控制软件平台。**

它的核心价值不是“让当前硬件转起来”，而是沉淀以下可复用能力：

- 电机控制系统对象模型。
- 功率输出安全边界。
- 电流、电压、位置等反馈链路抽象。
- 开环、FOC、电流环、速度环、位置环的控制流程入口。
- 启动、自检、待机、使能、运行、停止、故障的状态机。
- 参数、标定、故障、诊断和测试方法。
- 面向不同 MCU、功率级、电机和传感器的硬件适配层。

当前硬件坏掉或更换，不应导致软件平台失效。只要新硬件满足平台定义的外设能力、实时性和安全接口，就可以通过适配层迁移，并重新完成硬件相关验证。

---

## 2. 分层模型

```text
应用/关节层
  - 上位机命令、关节模式、目标值、通信协议、应用限位

电机控制平台层
  - 控制状态机
  - 开环/FOC/电流环/速度环/位置环
  - 参数与标定
  - 故障管理
  - 诊断与遥测

控制对象抽象层
  - PowerStage
  - PwmOutput / SvpwmModulator
  - CurrentSense
  - VoltageSense
  - RotorSensor / Observer
  - Timebase

硬件适配层
  - MCU 外设绑定
  - ADC/TIM/DMA/IRQ/UART/I2C/SPI/CAN
  - GPIO、使能脚、故障脚、板级比例系数

具体硬件实例
  - STM32F407 / STM32G4 / STM32H7 / 其他 MCU
  - V3P / 自研功率板 / 其他三相逆变器
  - 2804 / 关节电机 / 轮毂电机 / 夹爪电机
  - MT6701 / ABI / SPI 磁编 / Hall / 无感估算
```

原则：

- 控制算法不直接依赖具体引脚、ADC 编号、定时器编号。
- 硬件差异集中在 `board_config`、BSP、HAL port 或等价适配层。
- 控制平台只依赖接口契约，不依赖某个开发板。
- 更换硬件时优先替换适配层和参数，不重写状态机、诊断、故障和控制框架。

## 3. 核心对象模型

| 对象 | 职责 | 不应承担的职责 |
| :--- | :--- | :------------- |
| `MotorControlSystem` | 汇总状态机、控制环、故障、参数和诊断，是平台主对象 | 不直接操作 MCU 寄存器 |
| `PowerStage` | 管理功率级使能、失能、故障输入和安全关断 | 不计算 SVPWM 或控制环 |
| `PwmOutput` | 提供三相 PWM 原始输出能力，处理启动、停止、占空比边界 | 不决定电压矢量和控制策略 |
| `SvpwmModulator` | 将电压矢量转换为三相占空比 | 不关心具体 TIM 通道 |
| `CurrentSense` | 提供相电流原始值、零偏、比例、有效性和采样时间戳 | 不决定电流环目标 |
| `VoltageSense` | 提供母线电压和其他模拟量 | 不决定保护阈值来源 |
| `RotorSensor` | 提供机械角、电角度、速度估计和有效性 | 不承担位置环控制 |
| `ControlPipeline` | 组织开环、FOC、电流环、速度环、位置环 | 不绕过安全状态机 |
| `FaultManager` | 检测、分级、锁存、快照和恢复故障 | 不隐藏硬件故障细节 |
| `ParameterSet` | 保存单位、范围、来源、版本、标定和硬件绑定关系 | 不允许无来源魔法数 |
| `Telemetry` | 输出调试、状态、采样、故障和版本信息 | 不进入实时临界路径阻塞 |
| `HardwareAdapter` | 绑定具体 MCU 外设、GPIO、比例系数和中断入口 | 不承载平台业务逻辑 |

## 4. 硬件能力契约

平台可以迁移到不同 MCU 或功率板，但目标硬件必须满足最低能力契约。

| 能力 | 最低要求 | 推荐能力 | 验证要点 |
| :--- | :------- | :------- | :------- |
| 主频与算力 | 能稳定完成控制周期内的采样、变换、环路和故障检查 | 有足够余量支持日志、通信和后续扩展 | 最坏执行时间、抖动、CPU 占用 |
| PWM 定时器 | 至少三相 PWM 输出 | 中心对齐、互补输出、死区、刹车、同步触发 ADC | 频率、极性、死区、失能延迟 |
| ADC | 至少支持电流采样；两相采样为常见起点 | PWM 定时器同步触发、DMA、多 ADC 同步 | 零偏、比例、噪声、采样窗口 |
| 功率级接口 | 三相驱动输入和使能/失能路径 | 硬件故障输出、过流/欠压/过温保护 | 默认安全态、故障响应时间 |
| 母线电压 | 能测量或估算母线电压 | 带硬件滤波和校准路径 | 分压比、有效范围、过压/欠压判断 |
| 位置反馈 | 支持至少一种角度来源或无感估算条件 | ABI/SPI 磁编优先于低速 I2C 闭环 | 分辨率、延迟、跳变、异常状态 |
| 时间基准 | 有稳定周期调度入口 | 硬件定时器触发实时控制 | 周期误差、时间戳一致性 |
| 通信诊断 | 至少有串口或调试口 | CAN/CAN-FD/EtherCAT/RS485 等按产品定义 | 命令超时、数据有效期、故障上报 |
| 存储 | 可保存参数或由上位机下发 | 带 CRC、版本迁移和回滚策略 | 参数损坏、版本不符、默认值 |

不满足能力契约时，不应通过修改核心控制逻辑硬凑，而应降低控制目标、调整硬件方案或定义该平台不适用。

## 5. 迁移边界

### 5.1 可复用部分

更换 MCU、功率板、电机或传感器时，原则上应保持稳定：

- 生命周期状态机。
- 功率输出使能条件。
- 故障分级、锁存和恢复框架。
- 参数字典和单位约定。
- 诊断数据模型。
- 控制模式入口。
- 分阶段验证流程。
- 软件接口契约。

### 5.2 必须适配部分

以下内容通常随硬件变化：

- ADC/TIM/DMA/UART/I2C/SPI/CAN 外设实例。
- GPIO 引脚、复用功能、电平极性。
- PWM 频率、计数周期、死区和刹车配置。
- ADC 触发点、采样时间、通道顺序。
- 电流采样电阻、放大倍数、偏置和方向。
- 母线采样分压比和滤波。
- 编码器协议、分辨率、方向和零位。
- 电机极对数、电阻、电感、磁链、限流和热参数。

### 5.3 必须重新验证部分

即使核心代码复用，以下项目也不能继承旧硬件结论：

- 上电默认安全态。
- PWM 极性、死区和失能响应。
- 电流采样零点、比例、噪声和饱和边界。
- 母线电压比例和保护阈值。
- 编码器方向、延迟、跨零和异常行为。
- 相序、电角度零位和极对数。
- 电流环、速度环、位置环参数。
- 热边界、峰值能力和持续能力。

迁移成功的定义不是“编译通过”，而是“适配层通过能力契约，控制平台通过对应验收门”。

## 6. 当前参考平台 A

当前平台只作为第一套可测量、可调试、可复现的适配实例。

| 项目 | 当前实例 | 在平台中的角色 |
| :--- | :------- | :------------- |
| MCU | STM32F103C8T6 | 第一套 `HardwareAdapter` |
| 功率级 | DengFOC V3P/V3Pro | 第一套 `PowerStage` |
| 电机 | 2804 BLDC | 第一套被控对象 |
| 位置传感器 | MT6701 | 第一套 `RotorSensor` |
| PWM | TIM2 CH1/CH2/CH3 | 第一套 `PwmOutput` |
| 电流采样 | ADC1 IN8/IN9 两相原始采样 | 第一套 `CurrentSense` |
| 母线采样 | 当前不可用 | 后续 `VoltageSense` |
| 调试 | USART1 | 第一套 `Telemetry` |

该平台的结论只能证明“参考平台 A 适配成立”，不能自动证明其他硬件成立。其他硬件应建立自己的 `platform_xxx` 适配记录。

## 7. 推荐代码组织

```text
Core/
  App/
    motor_control_system.*
    control_state_machine.*
    fault_manager.*
    parameter_set.*
    telemetry.*

  Control/
    foc.*
    svpwm.*
    current_loop.*
    speed_loop.*
    position_loop.*
    open_loop.*

  Drivers/
    power_stage.*
    pwm_output.*
    current_sense.*
    voltage_sense.*
    rotor_sensor.*

  Platform/
    platform_f103_v3p/
      board_config.*
      adc_port.*
      pwm_port.*
      gpio_port.*
      encoder_port.*
```

当前代码尚未完全拆成上述目录，但已有雏形：

- `app_baseline` 是应用入口。
- `board_config` 是硬件绑定层。
- `motor_drv` 是功率使能层。
- `motor_pwm` 是 PWM 输出层。
- `motor_adc` 是 ADC 原始采样层。
- `mt6701` 是当前位置传感器驱动。
- `baseline_diag` 是诊断和静态验证入口。

后续重构代码时，应先稳定接口，再调整目录；不要为了目录漂亮破坏可验证性。

## 8. 平台开发顺序

推荐按能力逐级推进：

| 阶段 | 目标 | 功率输出 |
| :--- | :--- | :------- |
| BL0 | 可构建、可下载、版本可识别 | 禁止 |
| BL1 | 安全启动、默认失能、日志可用 | 禁止 |
| BL2 | ADC、母线、编码器静态可信 | 禁止 |
| BL3 | PWM、使能、失能接口 | 当前按条件通过，异常时回溯 |
| BL4 | 低风险开环，确认动作响应和停止边界 | 严格限幅；相序、方向和极对数作为 FOC-PRE 输入 |
| BL5 | FOC 与电流环基础 | 严格限幅 |
| BL6 | 速度/位置伺服基础 | 已验证边界内 |

每一级只证明本级问题，不提前宣称后续能力。当前实验阶段先完成 BL0~BL2 和低风险空载开环；FOC/电流环暂不实现。

## 9. 工业化表达

对内或对外沟通时，建议使用以下表述：

> 本项目建设的是一套可移植的 BLDC/PMSM 电机控制软件平台。当前硬件只是首个参考适配实例。核心控制逻辑、状态机、诊断、故障处理和验证方法保持复用；不同 MCU、功率板、电机和传感器通过硬件适配层接入。迁移时必须重新验证实时性、采样链路、PWM/功率输出、安全态和控制参数。

避免使用以下不严谨表述：

- “任何电机都能用。”
- “硬件不重要。”
- “换芯片不用验证。”
- “只要能编译就算迁移完成。”

更准确的说法是：

- “硬件不是架构中心，但硬件能力必须满足平台契约。”
- “软件平台可迁移，硬件适配和验证不可省略。”
- “当前平台是实例，不是系统定义。”
