# 00 · 文档总览（地图 / 台账 / 规则）

## 1. 文档分层模型

文档按抽象层级分目录，**下层服从上层，同层不互相重复**：

| 层 | 目录 | 回答的问题 | 变化速度 |
| --- | --- | --- | --- |
| L1 需求与选型 | `01_需求与选型/` | 为什么做、选什么、问题如何分解 | 最慢 |
| L2 架构设计 | `02_架构设计/` | 分几层、模块职责、平台契约 | 慢 |
| L3 规格与计划 | `03_规格与计划/` | 必须做什么、什么顺序、什么算通过（合同） | 中 |
| L4 硬件适配 | `04_硬件适配/` | 引脚、外设、功率板接口契约 | 硬件定后基本冻结 |
| L5 详细设计 | `05_详细设计/` | 代码怎么落地：结构、机制、取舍、资源预算 | 随代码演进 |
| L6 验证记录 | `06_验证与实验记录/` | 实测证据、标定报告、波形数据 | 持续追加 |
| 参考 | `07_参考资料/`、`assets/` | datasheet、业界调研、图片 | 按需 |

**核心边界**：L3 规格是"合同/验收标准"（稳定），L5 详细设计是"施工方案/实现机制"（随代码更新），代码本身是"how 的最终事实"。详细设计只写 why、契约、不变量与取舍，**不逐行复述代码**。

## 3. 文档状态约定

每份文档文头必须标注状态，四档：

- **草稿**：正在写，结构和内容可能大改；
- **已对齐**：与当前代码/事实一致，可作为依据；
- **滞后**：代码已变、文档未跟，仅作历史参考，需更新或并入；
- **废弃**：不再适用，保留留痕，不再维护。

## 4. 编号与三层追溯规则

- 文档编号：`REQ/ARC/SPEC/HW/DD/TST/REF-序号`，分册内小节用 `DD-01§4` 形式引用；
- **三层追溯链**：`规格条款(What) ↔ 详细设计(How) ↔ 代码符号(Where)`。
  - 例：`SPEC-CAL S1 ↔ DD-01§5 符号相序 ↔ control_loop 符号判定函数`；
- 互引用**稳定编号或函数名，不写行号**（行号会随代码变动失效）；
- 每个详细设计分册第 10 节必须回填它实现了哪些规格条款。

## 5. 维护规则（防腐烂，写入完成定义 DoD）

1. 代码是 how 的单一事实源，详细设计只写设计意图、接口契约、不变量、被否决的方案；
2. 改代码后必须检查对应分册，状态变化时更新文头"最后对齐"与本台账；
3. 新增模块：复制 `05_详细设计/_模板_子系统详细设计.md` 建分册，并在本台账登记一行；
4. 未确定内容统一用 `> 【待填写】……` 引导块，全文可检索 `【待填写】` 找到所有未完成点；
5. **分组收敛**：详细设计只按"已存在的代码簇"分册；尚未实现的能力（如速度环/位置环/力控）在相关分册内用占位小节预留，不新建文件、不新开目录。
