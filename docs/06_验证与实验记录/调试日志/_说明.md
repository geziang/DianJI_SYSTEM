# 调试日志（Debug Log）目录说明

## 定位
本目录是**经验/失败教训的复盘材料库**，不是痕迹记录、不是流水账。它沉淀一个故障从现象、假设、插桩、实验、证伪/证实到修复的完整思考链与证据链（L6 验证记录）。**读者关心的是"学到了什么、下次怎么不踩坑"，不是"那天干了什么"**——写"为什么这么查、怎么定位、为何这样改"，把一次踩坑榨成可复用的判断力。

与相邻目录/模板的分工：
- `../_实验记录模板.md`：**单次上电实验**的表格化记录（环境、激励、原始数据、判据）；
- `../标定报告/`：某标定步骤**通过后**的正式参数报告；
- `../波形与数据/`：原始波形、CSV、**原始串口日志（逐字留存，调试日志引用它而不是转述充当现场；来源与转引声明见该目录 `_来源说明.md`）**；
- 本目录 `调试日志/`：**踩坑的过程、原因与教训**，可同时引用上面三类材料；
- `_归档/`：**已被新认知整体取代的过程日志**（原文保留、结论以现行日志为准，见 `_归档/_说明.md`）。

## 命名规则
`YYYYMMDD_主题.md`，主题写"收获/转折"而不是"动作清单"——《从绕圈到转起来…踩坑复盘》优于《XXX排查与实施》。
同一主题多轮排查用同一文件持续追加（文头状态在受控状态词之间更新），不同主题新建文件。

## 证据等级标签（结论强制标注）
- `[A-实测]`：串口原文 / 仪器读数 / 操作者直接观察，必须能在 `../波形与数据/` 或实验记录中**逐字找到**；
- `[B-代码事实]`：对**当前源码**的逐行核查结论，引用稳定函数名/宏/分支名，不写易失效行号；
- `[C-推断]`：由 A/B 推理得到、未经实验判决；**禁止出现在文头状态行与 TL;DR 的肯定句中**；
- `[D-存疑]`：证据互相矛盾或原始记录缺失，必须显式列出竞争解释。

每篇日志文头放"证据可用性声明"：列出引用的一手记录、核查过的源码、以及哪些结论只有 C/D 级。

## 文头状态词白名单（只能五选一，禁止自造）
`进行中` ｜ `代码完成(未编译)` ｜ `已编译未上板` ｜ `上板验证通过(附实验记录)` ｜ `已证伪/废弃`。
- 写"上板验证通过"必须同段挂出实验记录文件名/原始记录，关键数值可溯源；
- 跨层故障允许且应当写**分层状态**（例："L1/L2 已验证、L4 未闭环"），**禁止用总括"通过"掩盖未闭环层**。

## 写作硬门（DoD，逐条可检查）
1. **数值可溯源**：每个串口数值/统计量都能在留存原文中检索到；禁止无出处的"带时间戳现场"，转引必须标注来源与"原文是否留存"；
2. **预测-实测回填闭环**：允许先写"预期打印/预期数值"，但上板后必须回填实测与一致性判定（含预测错的、没预测到的），未回填状态不得前进；
3. **证伪回溯义务**：新证据推翻旧结论时，旧日志文头加勘误块、新日志反向链接，不得让错误结论裸留在检索路径上；
4. **索引同步义务**：新建日志必须同步本文件索引表与 `../../00_文档总览.md` §7 变更记录；
5. **假设坟场留痕**：被否决/撤回的假设必须记录（当时说法、否决证据、现表述），不得删除痕迹；
6. **单次上电走模板**：单次实验记录用 `../_实验记录模板.md`，调试日志只引用、不内嵌、不把转述当原始现场。

## 勘误、归档与作废判定标准
- **事实性记录**（改了什么代码、当时打印了什么）永远保留；
- **结论性判断**（根因是谁、是否验证通过）被证伪 → 加勘误块与行内标注，**不删原文**；
- **整篇被新认知取代**（叙事框架被推翻，或同一主题出现更准确版本）→ 移入 `_归档/`、索引标注取代者，主检索路径只留最准确版本（原文不删、历史可溯）；
- 只有凭空编造、从未发生的"实验/数据"才允许移入作废归档；
- 勘误块格式：`> 【勘误 YYYYMMDD】①哪条结论被证伪/降级；②证据与指向的新日志章节；③仍有效的部分。`
- **勘误自身也走证据等级**：翻案/指控前必须回原始记录逐字核对，被推翻的判断要显式撤回——"勘误翻车"的度量/归因教训见 `20260912_经验6_*.md`，各归档文件文头【最终结论 2026-09-13】是勘误再勘误的示范。

## 写作要求（面向"复盘"，不是"记录"）
1. 区分**已证实（实验/代码事实）**与**推断/待验证**，结论给证据；
2. 关键串口日志、数值、代码符号可追溯（稳定函数名/宏，不写易失效行号）；
3. **写思考过程**：卡在哪、当时怎么想、为什么错、转折点在哪、谁在什么判断下拍的板——"神之一手"式的关键决策必须显式写出，不许淹没在时间线里；
4. **每篇必须回答"学到了什么、下次怎么不踩"**：结尾提炼可复用的方法论条目并回指正文；
5. **不确定就挂账**：未闭环的层显式挂账（分层状态），禁止"基本通过/应该没问题"式装闭环；
6. 记录被否决的方案与理由（避免以后重走弯路）；
7. 结尾给"当前状态 + 下一步"，并回填 `../../00_文档总览.md` 变更记录。
