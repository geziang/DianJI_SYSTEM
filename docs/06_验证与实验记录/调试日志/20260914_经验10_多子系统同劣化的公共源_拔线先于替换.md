# 经验10 · 多子系统同劣化：先找公共源，拔线先于替换

> 专题：编码器之乱（2026-09-13~14，两天三阶段：间歇失败→使能即死→总线深挂+ADC 劣化）
> 状态：**结案**——编码器板损坏拖拽 3.3V 轨，拔线判决（零偏秒过），待换新收尾
> 【勘误 2026-09-15】①"编码器拖垮电源轨"维持成立（拔线对照实验不变），但**只是并发病**：换新编码器后链路病（I2C 位错误/假转速/掉线）仍在；②系统级根因=**多源 3V3 硬并联拓扑**（ST-Link 供电型 3.3V/核心板 LDO/驱动板 LDO 同网裸并联，INA240 采样参考同网），拔 ST-Link 即愈——全案机理与拓扑证据见 `20260915_经验11_电源拓扑的隐性合同_多源3V3硬并联.md`；③本篇方法论（公共源思维/拔线先于替换）不受影响，且正是它把案子推到了拓扑层。

## 0. 本篇只讲两条

1. **两个互不相干的子系统同时劣化 = 公共源**（电源轨/地/接线），别分别修"两个病"。
2. **替换是花钱的实验，拔线是免费的同一实验且信息更多**（移除=方向性证明，替换=混合了"新件效应"）。

## 1. 病情三阶段（表象一步步骗人）

| 阶段 | 表象 | 当时最像的解释（全错） |
| --- | --- | --- |
| ① 间歇失败 | 400rpm 持续 35-40s 掉线；恢复需秒级 | "高速 EMI 抗扰"（部分对，但只是表象） |
| ② 使能即死 | 零流使能 <500ms 编码器死；断电 2s 自愈 → 后来 15s+ | "新加的代码触发的"（速度环无辜背锅） |
| ③ 深挂+扩散 | 总线跨 MCU 复位不复原；**ADC 零偏也开始 10/10 挂** | "MCU 坏了/程序太大供电不够" |

关键转折：阶段③的"两系统同劣化"——I2C（数字）与 ADC 零偏（模拟）互不相干，同时崩只能找公共层。

## 2. 软件嫌疑的逐一平反（每条都有代码/数据证据）

| 嫌疑 | 平反证据 |
| --- | --- |
| "速度环加进去就崩" | 时间线反证：掉线先于速度环存在（825d112 无速度环版同故障）；且该版本今天重烧实测健康 |
| "门禁阈值改严了" | git 历史：零偏判定文件速度环从未碰过；编码器门禁方向全是放宽 |
| "程序太大/供电跟不上" | Flash 半空、CPU +1~2%、MCU 功耗不变——性能不足与器件损坏是两种病，解法完全不同 |
| "编码器阻断了零偏/打印" | 零偏校准函数自包含（函数内零 I2C 调用），且采样期主循环阻塞其中、I2C 反而静默；打印逐行阻塞不丢行，状态机检查顺序是铁证词 |

**方法论：平反不是靠辩解，是靠"把每条嫌疑变成可查的代码/数据问题"**——git 历史查阈值、map 查尺寸、代码查调用路径、时间线查先后。

## 3. 定凶工具箱（本次实战排布）

1. **自愈可见化**（先造工具再看病）：BOOT 卡点打印+零偏重试+I2C 复活——把"无声等待"变成"有声自证"，阶段③全靠它定位到零偏门；
2. **冻结基线**（8 月固件当独立证人）：+编码器遥测打印后跑开环——证明"20kHz+稀疏读"下硬件能活，缩小变量面（PWM 频率/读取密度/ADC 同步）；
3. **git worktree 二分**：825d112（昨日验收版）原样复刻重烧——同代码昨天绿今天绿 → 排除该版本代码；**A-B-A 交叉的警告**：硬件随时间劣化会让"先后测"产生假因果，版本对照必须同时段交叉；
4. **分段暴露实验**（`e` 命令）：驱动静态/50% 开关/零流闭环三段各 2s——三段全过反证"静态使能链杀人"，指向间歇性；
5. **拔线判决**（终局）：拔编码器 → 零偏秒过（一行重试都没有，状态机顺序证明）→ **编码器板拖垮电源轨定罪**。

## 4. 复盘：哪一步本来可以更快

| 实际路径 | 更短路径 |
| --- | --- |
| 阶段②先怀疑新代码，做了 git 二分 | "同工况昨绿今死"一查构建号即可排除代码——**先对时间线，再审嫌疑犯** |
| 阶段③先补自愈/实验工具再定位 | 工具值得，但"两系统同劣化"出现时就该直接做拔线判决——**公共源思维要更早启动** |
| 摇线试验提了三次没执行 | 拔线判决本质是摇线的终局形态，早做早结案——**免费的实验别拖到花钱的实验之后** |

## 5. 预测-实测回填（按经验6纪律）

| 预测 | 实测 | 判定 |
| --- | --- | --- |
| "编码器问题只在功率开关期"（阶段②模型） | 阶段③断电态零偏也挂 | **错**——模型随病情升级须重估 |
| "e 实验三段会抓到凶手段" | 三段全过（间歇性） | **错**——确定性实验抓不住间歇凶手，但反证有价值 |
| "拔编码器后零偏恢复" | 一行重试都没有，直接过编码器门 | **对**——判决成立 |

## 6. 假设坟场

① 速度环触发（时间线反证）；② 门禁变严（git 反证）；③ 程序太大/供电不够（尺寸/功耗反证）；④ 软件阻塞零偏（代码自包含反证）；⑤ 磁环松脱（i-rotate 跟随反证）；⑥ 纯 EMI 干扰（拔线后零偏恢复证明是"拖垮电源轨"而非"干扰信号"——机理修正）；⑦ MCU 芯片损坏（"安静时完美"不合硅损特征，且拔线即愈）。

## 7. 迁移用法

1. 多子系统同劣化 → 列公共资源清单（电源轨/地/时钟/总线/温度），逐个做"移除式"实验；
2. 换件冲动出现时先问：拔掉它能不能得到同样的信息？（多数时候能，还免费）；
3. 间歇故障 ≠ 不能定位：让它"可见"（计数/打印/分段）+ 移除实验交叉，一样能结案；
4. 给继任者留自愈与诊断工具，别只留结论——本篇的第 3 节工具全部固化在 F103-run 固件里。

## 8. 一句话带走

**两个不相干的子系统同时变坏，先找它们的公共资源，再谈各自的病；而"拔掉它试试"永远排在"买个新的换上"前面——免费的实验先做，方向比替换更干净。**
