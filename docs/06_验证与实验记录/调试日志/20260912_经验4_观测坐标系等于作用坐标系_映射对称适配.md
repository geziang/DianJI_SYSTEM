# 经验4 · 观测坐标系必须等于作用坐标系：映射要在全部适配点对称

> 专题：编码器方向 × 相序定序（2026-09-12）｜状态：**修复保留、上板验证硬发散消除**；但它不是 S7 通过的充分条件（L4 残留，见 `20260912_L4_dq固定偏转_挂账与判决实验.md`）

## 0. 本篇只讲三条

1. **闭环成立的前提：控制器"看到的状态向量"和它"施加作用的状态向量"必须在同一坐标系。** 任何映射/重排/符号变换，都要对称地施加到**每一个跨边界适配点**，只改一侧 = 反馈错位。
2. **恒等映射是完美掩体：只测 perm0 永远发现不了不对称。** 测试矩阵必须含非恒等 case；要能预判"第一个非恒等 + 真闭环"的时刻在哪。
3. **命名一词二义会把不对称藏起来。** 用命名/强类型把"物理通道"和"逻辑相"分成两种东西，让拿错的动作在接口处就无法隐式发生。

---

## 1. 这个坑怎么撞上的（最小背景，自包含）

FOC 闭环：ADC 读相电流 → Clarke/Park 变到 dq → PI 算 dq 电压 → 反变换/SVPWM → 三路 PWM 占空比。相序 perm（phase_map）负责把"逻辑相 A/B/C"对应到"硬件通道 0/1/2"。

修复前两侧不对称（[B] 代码事实）：
- **输出侧**（`foc_runtime.c` ISR）：按 phase_map 把逻辑相占空比重排到硬件 PWM 通道——**有映射**；
- **测量侧**（`foc_current_model.c`）：把通道 U/V 的原始 ADC 码**直接当逻辑 A/B**——**没有映射**。

非恒等 perm 下就出现："逻辑 B 的电压打到通道 2，逻辑 B 的电流却从通道 1 读回"。控制器在一个坐标系施加作用、却在另一个坐标系观测结果，dq 帧交叉耦合。22:17 的 S7 两行（iq +0.93→−0.86 正负反打、电压矢量 52ms 冲到 5.50V 满限幅）就是这个形态的硬发散。

## 2. 三条经验讲透

### 2.1 观测坐标系 = 作用坐标系，映射对称施加到全部适配点

闭环控制本质是在某个状态坐标系里最小化误差。如果观测到的状态向量相对作用坐标系差了一个固定变换 T（这里是通道置换），那 PI 拼命拉的"误差"根本不是真实误差：轻则稳态偏转（分量落错轴，正是 L4 的嫌疑方向），重则正反馈发散（本案 22:17）。

**纪律：引入任何"逻辑 ↔ 物理"的映射时，列出所有跨越这条边界的适配点，逐一证明用了同一张表。** 本案有两个电流相关适配点：
- 功率输出边界（逻辑相电压 → 硬件 PWM 通道）；
- 测量输入边界（硬件 ADC 通道 → 逻辑相电流）。
（角度/dq 零位约定可能是第三个适配点，L4 在查。）

修复做法（两步式对称路由，保留至今）：
```
第一步：按各通道自己的零偏/符号求通道电流 ch0/ch1，ch2 = −ch0−ch1（基尔霍夫重构）
第二步：逻辑相 x 的电流 = ch[phase_map[x]]；map 非法（越界/重复）时回退恒等 = 安全回退
```
关键点：每通道的零偏、符号（S1a 标定的是**通道**属性）始终绑在通道上、随通道路由——这才叫对称。数学上置换不破坏 `ic=−ia−ib`：三通道和为零，`−ch[map_a]−ch[map_b]=ch[map_c]` 恒成立。

### 2.2 恒等映射是完美掩体，预判第一个"非恒等 + 闭环"点

为什么这么直白的错能藏到 S7 才炸？三个结构性原因：
1. **perm0 恒等 = 假阴性**：S0–S4 全部在 perm0 下跑，恒等映射时"输出过表、测量不过表"结果逐字节相同，怎么测都对；
2. **管线顺序决定爆点**：S1b/S4 的闭环发生在 PHASE_SEQ 改 map **之前**（还是 perm0），PHASE_SEQ/S5 只跑开环电压（测量值只打分、不参与打仗），于是全流程第一个"非恒等 perm + 真闭环"的时刻恰好就是 S7——前面全绿、到 S7 才炸；
3. **θ=0/π 简并点免疫**：S5 只在对齐点工作，而对齐点 b=c，B/C 互换不改变任何物理量，错了也不报警（与经验3 的简并同源）。

**纪律**：
- 测试矩阵必须至少含一个**非恒等**变换，恒等通过 ≠ 正确；
- 改映射类代码时，顺着数据流走一遍，明确指出"第一个非恒等且真闭环"发生在哪一步，重点查那一步之前的所有准备是否都按非恒等验证过；
- "前面全过、最后一步炸"高度提示某个适配点漏了映射，而不是最后一步自己的算法问题。

### 2.3 命名一词二义会掩盖不对称，用类型/命名把两种语义分开

错误能长期隐身，命名帮了倒忙：结构体字段叫 `phase_a_raw`，注释却写"两相原始 ADC 输入"（这是**通道**语义）。一个名字同时指"物理通道 U"和"逻辑相 A"，读代码时大脑会自动把两者当成一回事，输出侧用 phase_map、测量侧"看起来也在用 phase"，不对称就被名词抹平了。

修复做了 channel/phase 命名分离（14 处：`phase_a_raw→channel_u_raw`、零偏/符号字段同步），并把契约写进类型注释：`foc_phase_map_t`——"**必须对称应用在 PWM 输出与 ADC 输入两个适配点，只应用一侧 = 电流环反馈错位**"。

> C 语言没有强类型别名，靠命名约定 + 契约注释守住；C++ 里可以直接 `using channel_idx_t=...; using phase_idx_t=...` 做成不同强类型，让"把通道当逻辑相传"在编译期就报错。**让错误的表示无法隐式地伪装成正确的表示**，是这一条在语言层面的一般化。

### 2.4 诚实边界：必要，但不是 S7 的充分根因

对称修复后，方案 A 两轮 S7 仍有残留（id≈0.31、iq≈0、dyn_R 被拒，即 L4）。所以准确表述是：测量侧不对称是**真实缺陷、必须修、且它就是 22:17 硬发散的主因**（修复后硬发散消失，见经验5 的记功），但"修了它 S7 就该通过"不成立——**修复必要 ≠ 根因已除**。这种"贡献层"和"充分根因"的区分，见经验5/经验6。

## 4. 一句话带走 + 迁移用法

**一句话：闭环的观测坐标系必须等于作用坐标系；任何映射在所有跨边界适配点对称施加，并用非恒等 case 和分离命名防复发。**

迁移 checklist：
1. 引入坐标/通道/单位/序的映射时，列全"出边界"和"入边界"的每一个适配点，逐一核对同一张表；
2. 变换写成单一事实源（一张表/一个函数），禁止在不同适配点各写一份隐式映射；
3. 测试必含非恒等用例，并预判"第一个非恒等+真闭环"的位置重点设防；
4. 两种语义用不同命名（C）或强类型（C++）分离，让错配无法隐式发生；
5. 非法/异常映射回退到安全的恒等行为，不静默产出错位结果。
