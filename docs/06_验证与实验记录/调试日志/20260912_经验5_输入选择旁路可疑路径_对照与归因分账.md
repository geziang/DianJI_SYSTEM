## 0. 本篇只讲三条

1. **单变量对照：冻结一切、只动一个自由度，两轮之间的任何差异都只能归因于它。**
2. **更强的一招——用输入选择旁路可疑代码路径：让唯一的自变量恰好是"嫌疑代码是否被触发"，零代码改动就完成隔离，一次实验同时做到验证猜想、达成目标、定位病灶。**
3. **归因分账："修完 X 之后好了" ≠ "X 治好了它"。** 多个修复在时间上相邻时，必须用对照把各自的功劳分开。

## 1. 这个坑怎么撞上的（最小背景，自包含）

旧流程 ENCODER_DIR 步在测得方向翻转时，会执行一段"方向翻转 + 联动镜像 phase_map"代码（打印 `[DIR] direction flipped ... mirror phase_map`）。现象是：按固件提示**顺时针**手转，流程总走不完（22:17 在 S7 两行即炸；另两轮一次 S5 静默 FAULT、一次 ok=0 被门禁拦）；而每一次顺时针都恰好经过"direction 翻成 −1 → 联动镜像"这条路径。

当时测量侧对称修复（经验4 的 L3）已经在当天早上完成并烧入，方案 A（删联动、DIR 前置）还没做。

## 2. 三条经验讲透

### 2.1 单变量对照：冻结一切，只留一个自由度

可信对照的硬性条件：
- **硬件冻结**：接线、电源、电机、编码器位置全程不动（本案明确没动任何线）；
- **固件冻结**：对照两轮之间不改代码、不重新烧录；
- **流程冻结**：S0–S7 原样跑，每步激励相同；
- **唯一变量**：ENCODER_DIR 步手转方向（CW / CCW）。

满足这四条，CW 与 CCW 两轮之间出现的任何差异，因果上只能来自手转方向，排除了"是不是又改了别的"这类干扰。这是后续一切推断成立的地基。

### 2.2 输入选择旁路：让自变量 = 嫌疑路径是否被触发（核心技术）

普通对照是"改一个输入看结果"；更进一步的是**精心选这个输入，使它恰好能"不执行"某段可疑代码**，从而在不改一行代码、不烧录的前提下，把嫌疑人隔离掉。本案：

- 可疑路径：`if(direction != prev) best^=1` 联动镜像块，它只在方向从默认 +1 翻成 −1 时触发；
- 输入选择：固件提示顺时针，**偏手转逆时针** → 测得 `direction=+1`，翻转条件不成立，**整条"方向翻转+联动镜像"路径不执行**（verify 的第一次镜像两轮都会走，被旁路的嫌疑人精确地只有 DIR 这一段）；
- 结果：电机第一次稳稳转起来，S7 全窗 2.46s、49 行 S7DBG 稳定、无鸣叫无复位。

这一次实验同时完成三件事（高效率的来源）：
1. **验证猜想**：不触发翻转就能转 → 翻转路径确实是病灶；
2. **达成目标**：电机当场转起来，不用等改代码；
3. **定位病灶**：转动的相位没被程序翻转过来，病灶钉死在 `DIR_MANUAL_DONE` 联动块，而不是泛泛的"相序问题"。

> 一般化：当你怀疑某段代码/某个分支有问题，先问"有没有一个**合法输入**能让这段代码不被执行？"——用输入把它旁路掉，比注释掉、加开关、改代码再烧录都快，且不引入新变量。这是"最小干预隔离"在嵌入式上的形态：物理输入本身就是最干净的开关。
>
> 还有一层巧思：手转方向是全系统里**唯一 100% 确定的真值输入**（人手知道自己往哪转）。把它从"不可控扰动"反过来用成"已知真值注入"，CW/CCW 各测一次，就给经验1 的欠定方程补上了第二个独立方程。

### 2.3 归因分账：修完 X 后好 ≠ X 治好它

0912 当天有两个修复时间相邻：早上的测量侧对称修复（L3，经验4）、随后的方案 A（删联动+DIR 前置，经验1）。电机转起来是在"含 L3、方案 A 前"的对照 CCW 轮——这恰好把功劳分清楚了：

| 谁消除的 | 证据 |
| --- | --- |
| **硬发散（22:17 那种 iq 反打、电压满幅、鸣叫）= L3 测量侧修复** | 对照 CCW 轮已含 L3、**还没有**方案 A，S7 就已全窗稳定不发散 |
| **路径依赖（终态随手转方向变、正确性靠对消）= 方案 A** | 方案 A 后两轮终态成为结构保证、无 flipped、正反等价（经验1/经验2） |

如果只看时间线"方案 A 烧完电机能转"，很容易把两件事都记在方案 A 头上，进而错误地以为"方案 A 能治 S7 一切问题"——这会误判 L4。归因纪律：
- 相邻多个改动，找一个"含 A 不含 B"的中间状态做对照，让每个效果都能找到唯一来源；
- 记功/记过都精确到"哪个现象是哪个改动消除的"，不打包；
- 时序相邻 ≠ 因果，"之后"不等于"因此"（post hoc 谬误）。

## 4. 一句话带走 + 迁移用法

**一句话：冻结一切只动一个自由度；最高效的隔离是选一个合法输入让可疑路径不被触发；多个相邻修复必须分账归因。**

迁移 checklist：
1. 做对照前逐条确认硬件/固件/流程冻结、唯一自变量是什么；
2. 怀疑某分支时，先找"能让它不执行的合法输入"，用输入旁路代替改代码，做到零新变量隔离；
3. 一次实验尽量同时承担"验证/达成/定位"，但结论分别陈述、不混为一谈；
4. 多个修复后现象消失，主动构造"含这个不含那个"的中间对照，把每个现象归因到唯一改动；
5. 把系统里最确定的输入（人手动作、已知信号）当真值注入，用来给欠定问题补独立方程。
