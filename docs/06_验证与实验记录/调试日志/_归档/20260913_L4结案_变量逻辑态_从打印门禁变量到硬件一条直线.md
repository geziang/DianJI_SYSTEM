## 0. TL;DR（只放已证实句）

L4 不是坐标系病、不是硬件器件病——**是判据的观测通道病**：编码器 5ms 轮询在 ωe≈78 rad/s 下造成约 16.7° 电角滞后 [A③④推导+⑤复现]，EMF 经 sinδ 把 ~0.25V 泄漏进 d 轴压低 wvd；瞬时打印又被 50ms 遥测周期与台阶激起的振荡"锁相混叠"，制造了"id̄=0.31、iq≈0、V⊥I、104° 偏转"的幻影（历靴表象随速度漂移即其指纹）。修复＝**编码器轮询 5→1ms（I2C 总线原本 91% 空闲）＋工作点临界大信号稀释**，S7 史上首次产出候选并落盘成功 [A⑤]，断电重启 `[LOAD]` 逐项一致 [A⑥]。
方法论教训（本篇主旨）：**问题在半山腰（台阶理论成型时）就已经定位到了变量，但我们没有走完"打印→门禁→变量→值为何不满足→映射硬件→盘查资源余量→按硬件特性修改"的直线，反而在判据/算法层多绕了四轮构建**——最后走完直线的关键一问（"I2C 极限是多少"）是操作者问出来的。

## 2. 绕圈复盘：变量其实早就定位了（本篇的核心自省）

**"已知道什么 vs 当时在做什么"时间线：**

| 时间点 | 已经知道什么（证据） | 当时实际在做什么 | 差距 |
| --- | --- | --- | --- |
| 静态审计轮（VJ 前） | 智能体书面评估"编码器 5ms 过期 ≈4°，可忽略"——**速度量级估错**（ωe 按 ~14 估，实际 78~130） | 排除软件帧不一致（该做，且必要） | 变量值算错→排除错：4° 实为 17°。**智能体估算失误，点名留档** |
| VJ 判决后（台阶理论成型） | **源头已点名："编码器 5ms 台阶 × 旋转"**——变量 δ=ωe×T_poll 已握在手里，17° 量级可算 | 依次做了：窗均值探针→判据 v2.0→v2.1 窗回归设计→大信号整定——**全部在判据/信号层打转**，共四轮构建 | 变量已定位，但没人问"这个变量由哪个硬件资源承载？资源还有多少余量？" |
| 操作者问出关键一问 | **"我们增加编码器频率做一下实验，目前频率是多少，I2C 极限是多少？"** | （此前智能体给出的"根治方案"是角度外推——软件复杂件，还因 ROM 受限挂账） | 0.45ms 阻塞读 / 5ms 周期＝**总线 91% 空闲**，轮询 1ms 零成本可得——**这一问走完了直线，是用户问出来的** |

**精确表述**：中途定位到的是"嫌疑机制"（台阶理论），没定位到"**变量逻辑态**"——后者五要素：变量名（角度滞后 δ）／当前值（17°）／需要值（sinδ·EMF ≪ R·id，即 δ 足够小）／**承载硬件（I2C 轮询周期 × 总线速率）**／**资源余量（91% 空闲）**。前三个要素 VJ 后已齐，后两个直到操作者发问才补上——**这个差，就是四轮绕行的全部成本**。
另记一笔公道：操作者更早的直觉"可能与硬件有关"（当时被 VJ 的"器件无罪"部分顶回）——事后看方向是对的，病灶确实是**硬件资源（总线带宽/轮询周期）**，只是不是"器件坏了"那种硬件。直觉指向了正确的类别，术语上被误解为错误的子类。

## 3. 方法论：变量逻辑态五要素＋"资源优先于算法"

**链条（打印 → 硬件的直线，每步一个检验问题）：**

```
串口打印 → ①哪个门禁拦的？（智能体查代码定位判据）
        → ②门禁读的是哪个变量？（变量=有明确物理含义的量）
        → ③变量的当前值 vs 需要值差多少？为什么？（建立方程，不建方程不算定位）
        → ④这个变量在板上由哪个物理资源承载？（角度新鲜度↔I2C轮询周期×总线速率）
        → ⑤该资源还有多少余量？有余量→直接调资源；没余量→才轮到算法层绕行
```

- **五要素完成态**：变量名／当前值／需要值／承载硬件／资源余量——**缺一不算定位完成，缺后两个最危险**（因为会像本案一样：变量都看见了，还在给硬件带宽问题写软件补丁：窗均值统计、外推、回归……每一个都"有道理"，每一个都不是最短路径）。
- **资源优先于算法**：修资源（提频/提幅/提速率）改的是物理供给，语义不变、风险低、常常更便宜；算法手段（统计、外推、补偿）是资源不足时才用的第二顺位。本案顺序反了：先设计了回归数学，后被 1ms 轮询一句"我不需要了"。
- **人机分工（接经验7）**：智能体擅长跑①②的机械链条（打印→门禁→变量，它一次就查对了）；**③的方程化和④⑤的硬件映射/余量盘查必须人来问**——本案 ③ 是双方一起完成的（δ 方程），④⑤ 是操作者独扣的一分。

## 5. 假设坟场（当天的说法 → 否决证据 → 现表述）

1. **L4=C1/C2/C3（坐标系错位三候选，0912 挂账篇）** → 否决证据：VJ 22 位置响应无角依赖、扫描正向自旋（记录②） → 现表述：对象（测量系/输出系/角度链/换相）无罪，病在判据的观测通道。
2. **"EMF-free 判据 v2.0（wvd/wid 即 R）"** → 否决证据：dyn_R=0.9876 与 δ=16.7° 解算（记录④） → 现表述：d 轴在 δ≠0 时被 EMF·sinδ 污染；正确形态是窗序列线性回归斜率（v2.1，已设计、因资源提频失去必要性而留档不实施）。
3. **"编码器 5ms 过期≈4° 可忽略"（智能体，审计轮）** → 否决证据：ωe 实测 78~130 rad/s → 现表述：当时就应按"变量值可疑"挂账而非书面排除；速度量级是本案第一个被估错的数。
4. **"MicroLIB 可作 ROM 腾挪选项"** → 否决证据：不支持 %f → 撤回；ROM 腾挪只剩裁打印/删遗留代码。
5. **"混叠论"（探针前提出）** → 证实而非否决：wid≈目标实锤 → 保留并升级为定论。
6. **"角度外推是唯一根治"** → 降级：1ms 轮询先行后外推不再必要；若未来 ωe 再升一个量级（速度环 M-F）滞后重新吃紧，外推（或 Phase B 400kHz）按本篇 §3 链条重新评估。

## 7. 一句话带走

**定位的完成态不是"找到嫌疑机制"，而是"变量逻辑态"五要素——尤其最后两要素（承载它的硬件、硬件还剩多少余量）；资源有余量就先修资源，算法绕行是第二顺位。** 半山腰看见山顶不等于登顶，差的那两问（变量活在哪个硬件上？余量够不够？）只有人会问——智能体会给你一打正确的算法，但它不会替你问"能不能直接把编码器读快一点"。
