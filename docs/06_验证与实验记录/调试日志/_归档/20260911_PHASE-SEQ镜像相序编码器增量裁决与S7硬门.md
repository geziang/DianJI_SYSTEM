## 0. 结论速览（TL;DR）

> 【已证误 20260912，见新日志 §5.2】下述"故障链（高置信）"中 1.6A 系 5.5/3.4 纸面推算、vbus 未采样、RCC_CSR 未读，且 22:17 实为用户手动 NRST（未断电），"母线塌陷→brown-out 自动复位"不成立；仅"换相错误下 S7 电流发散、鸣叫"为实测。
1. **故障链（高置信）**：镜像相序未裁决 → S7 换相反向 → iq 驱动**无净力矩（电机不转）** → PI 积分顶到 max_voltage=5.5V 限压 → 5.5V/3.4Ω≈1.6A 超出台电源 CC → 10V 母线塌陷 → 3.3V 跌落 → **brown-out 复位**。编码器链 `[FAULT] S7 encoder chain` 是受害者，不是元凶。
2. **根因①（判据太弱）**：静态 d 轴探针对 B/C 互换（镜像排列 `idx^1`）**原理上不可分**（θ=0 时两种排列读数完全相同）；旧 verify 用 3ms 瞬态 Iq 符号判决，实测 Iq 仅 ±0.03A、低于 0.15A 门限 → **永远 inconclusive** → best 在 perm0/perm1 间跨 boot 随机翻转，S7 是否踩雷全凭运气。
3. **根因②（深层机制）**：ENCODER_DIR 在 PHASE_SEQ **之后**无条件覆盖 `encoder_direction`。方向一旦翻转，已裁决的 (perm, dir) 自洽组合被破坏——这就是"verify 永远治不住本"的原因（S1a PROBE3 sign=-1 提示本机编码器方向为 −1，与默认 +1 相反，必触发）。
   > 【勘误 20260912】现象定位（DIR 在 PHASE_SEQ 之后、默认 dir=+1 与本机 e=−1 冲突）**正确**；但本日志开出的药方（§3.2 事后联动镜像）错误，它只是用第二次翻转补偿第一次，构成跨状态双重翻转路径依赖。正解：ENCODER_DIR 前置先独立定 e，verify 再一次定解 m（方案 A），见新日志 §3。
4. **修复（本次代码改动）**：
   - verify 判据从"瞬态 Iq"改为**编码器角度增量**：+90° 阶跃保持 300ms 让转子机械就位，`Δelec = pp × encoder_direction × Δmech`，预期 +1.571（一致）/ −1.571（镜像），窗口 [0.70, 2.40] rad 外判 inconclusive。编码器是数字量，噪声问题从源头消失。
   - ENCODER_DIR 翻转方向时**联动镜像 phase_map**，保持"正指令 → 正测量"关系不变。
   - S7 入口 `phase_seq_verified==0` 从"警告放行"改为**硬门拒绝**。

## 2. 根因分析

### 2.1 镜像相序为什么静态判不出

PHASE_SEQ 的 6 换相静态探针在 θ=0 注入 +Vd 读 (Id, Iq)。θ=0 时 b/c 相电流相等，**镜像排列（下标 `idx^1`，即 B/C 输出互换）与正确排列读数完全相同**——数学上对镜像不变。只有 θ 推进、磁场旋转时手性才暴露：同向旋转出净力矩，反向旋转力矩自我抵消。

### 2.2 旧 verify 为什么永远 inconclusive

旧实现已意识到要"+90° 探针"，但判据选错了物理量：矢量瞬切 +90° 后只在 3ms 瞬态窗采 Iq（刻意不让转子动）。实测该瞬态 Iq 仅 ±0.03A，而判决门限 0.15A——信号比门限低 5 倍，落在噪声带里，结论恒为 inconclusive。且 `TEST_STEP_CAPTURE` 入口对 inconclusive 只警告不拦截，于是带雷进 S7。

### 2.3 ENCODER_DIR 覆盖问题（深层）

FOC 自洽条件是 **(phase_map, encoder_direction) 组合**满足"正指令 → 正测量"。PHASE_SEQ 的裁决绑定的是当时的 `encoder_direction`（默认 +1），而 ENCODER_DIR 步骤随后按手转结果**无条件覆盖**它。本机编码器实际方向为 −1（S1a PROBE3 sign=-1/-1 佐证），覆盖后组合被破坏 → 镜像复发。这解释了为什么偶发"best 正确"的轮次 S7 依然失败。

### 2.4 复位链（为什么电机不转 + MCU 重启）

> 【已证误 20260912，见新日志 §5.2】本段复位链为纸面推算：1.6A 由 5.5V/3.4Ω 估算、vbus 未采样、RCC_CSR 未读；22:17 实际为用户手动 NRST（未断电）。"电机不转/发散"实测成立，"母线塌陷→brown-out 自动复位"不成立，P1 打印复位原因后此类事件才可判。

换相反向后 iq 不产生净力矩 → 电机不转（用户直接观察到的现象）→ 速度/电流误差累积 → PI 积分顶到 max_voltage=5.5V → 堵转电流需求 ≈5.5V/3.4Ω≈1.6A 远超台电源 CC 限值 → 10V 母线塌陷 → 3.3V 跌落 → brown-out 复位。前一轮"串口逐字符滴出"是同一塌陷过程中外设欠压的另一种表现。

```
d_elec = pole_pairs × encoder_direction × wrap(Δmech)
  d_elec ∈ (+0.70, +2.40) rad  → 与假定映射一致，保持 best，verified=1
```

## 4. 安全性论证

- **机械行程**：+90° 电角度 = 90°/7 ≈ 12.9° 机械角，单次阶跃，无往复；远小于 S7 全速旋转的行程风险。
- **电流水平**：沿用 ALIGN 1.5V ≈ 0.44A（3.4Ω），与 S1 已验证的 d 轴注入同量级，远低于 S7 堵转时的 1.6A 需求。
- **失败语义**：转子未跟踪（卡滞/摩擦大）或编码器异常 → Δelec 落窗外 → inconclusive → S7 被硬门拦截，**失败方向是"不让转"而非"带雷转"**。
- **看门狗**：全流程 ≈1.6s < 5s 超时，余量充足。
