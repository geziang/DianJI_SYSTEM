## 0. 结论速览（TL;DR）

1. **故障**：0911 修复后 verify 完美裁决镜像（perm1, dir=−1 自洽）、S5 ok=1，但 S7 仍 52ms 内失控：`iq=±0.93A`（目标 0.18A）、vd/vq 顶向 5.5V 限压 → ~~brown-out 复位~~【已证误：手动 NRST、未断电，见新日志 §5.2】。表象："短暂旋转→暂停→鸣叫"。
2. **根因**：phase_map 只应用在 **PWM 输出侧**（`foc_runtime.c` ISR），**电流测量侧完全不经过它**（`foc_current_model.c` 通道硬连线为逻辑相）。perm0（恒等）时两路天然一致、全部静态测试通过；一旦换 perm1，输出换了、测量没换 → 电流环反馈错位 → ~~任何角度立即正反馈~~【勘误 20260912：该不对称是真实代码缺陷、修复保留；但"任何角度立即正反馈=S7 充分根因"被方案 A 后两轮同构残留证伪，降级为必要非充分，见新日志 §4.3；22:17 的硬发散主因是 L2 双重翻转得到错误组合 perm1/dir−1】。
3. **为什么能藏住**：① perm0 恒等映射是完美掩体——整条标定链（S0–S4）都在 perm0 下自测通过；② 管线顺序保证第一个"新 perm+闭环"时刻是 S7（S1b/S4 在改 map 之前，PHASE_SEQ/S5 只跑开环）；③ 静态探针 θ=0 是镜像简并点，测量错也不报警；④ 症状与镜像相序 bug 逐字相同（电流失控→母线塌陷→复位），被上层 bug 挡住。
4. **修复**：测量侧对称路由 + channel/phase 命名矫正（详见 §3）。

用户观察："S7 短暂旋转后暂停然后鸣叫"。这是**反馈错位型失控**的教科书症状：初始电压产生真实力矩（转一下）→ dq 帧交叉耦合使平均力矩归零（暂停）→ PI 限幅振荡（鸣叫）→ ~~母线塌陷复位~~【已证误：手动 NRST；且"反馈错位型失控=测量侧不对称单独导致"的定性被新日志 §4.3 降级，硬发散主因是 L2 错误组合】。

**排除项**（逐一验证后锁定测量路径）：
- 角度链无问题：运行时 `θ̂=pp×dir×mech+offset`（`foc_angle_math.c:50`）与 verify 数学模型逐字一致；S5 offset 公式自洽；S7 每 1ms 经 `control_loop.c:2514` 喂编码器角度。
- verify 裁决可信：它只用编码器（数字量）+ 开环电压，不经过电流测量。
- PI 无问题：S4 阶跃 53ms 收敛、稳态误差 0.739%。
- 传感器无问题：S0 零偏 OK、S1b 在 perm0 下 0.2A 闭环误差 +0.005A。

## 2. 根因：精确到代码行

### 2.1 两行代码的对照（不对称的现场）

**输出侧**（`foc_runtime.c:243-250`，ISR 内，**有**映射）：
```c
ch[foc_runtime_parameters.phase_map.phase_a_output] = ...pwm.phase_a_ticks;
ch[foc_runtime_parameters.phase_map.phase_b_output] = ...pwm.phase_b_ticks;
ch[foc_runtime_parameters.phase_map.phase_c_output] = ...pwm.phase_c_ticks;
```

**测量侧**（`foc_current_model.c:44-54`，**无**映射）：
```c
phase_a = ...amp(raw->phase_a_raw, calibration->phase_a_zero_raw, ...);
phase_b = ...amp(raw->phase_b_raw, ...);
sample->phase_current_a.phase_a = phase_a;   /* 通道U 直接当逻辑A */
```

而 `foc_runtime.c:220-221` 装载的是 `raw.phase_a_raw = sample->phase_u_raw`——通道 U 的原始码。**perm1 下：逻辑 B 的电压打到通道 2，逻辑 B 的电流却从通道 1 读。**

### 2.2 为什么会写成这样（三层工程原因）

1. **命名一词二义（channel 冒名 phase）**：`foc_types.h` 的 `foc_raw_current_sample_t` 注释写"两相原始 ADC 输入"（通道语义），字段却叫 `phase_a_raw`；`foc_current_calibration_t` 的零偏/符号字段同理。S0/S1a 的数据源全部是通道属性（`phase_u_zero_raw`、`sign_u`），存进"phase"命名的字段后，语义漂移完成。恒等映射下无人察觉。
2. **设计契约只写了输出侧**：`foc_phase_map_t` 的原始注释是"值 0/1/2 分别表示控制器 A/B/C **输出**对应的硬件 PWM 通道……适配层接入 **PWM** 时应用该映射"——契约里根本没有 ADC 输入这回事，实现者照契约办事不算错，**错在契约**。
3. **测试矩阵不含非平凡置换**：所有闭环验证（S1b/S4）发生在 PHASE_SEQ 改 map 之前；PHASE_SEQ/S5 用开环电压（测量值只打分不打仗），且 θ=0 是镜像简并点。第一个"新 perm+闭环"时刻 = S7 = 雷炸点。

## 3. 修复清单

### 3.1 功能修复：测量侧对称路由

`foc_current_model_convert` 增加 `const foc_phase_map_t *phase_map` 入参（调用点仅 `foc_runtime.c` 一处，传入 `foc_runtime_parameters.phase_map`）：

```
第一步：按通道零偏/符号求通道电流 ch0/ch1，ch2 = −ch0−ch1（基尔霍夫重构）
第二步：逻辑相 x 电流 = ch[phase_map[x]]（map 为空或 A/B 非法时回退恒等）
第三步：ic = −ia−ib（排列置换下恒等于 ch[map_c]，无需显式查 map_c）
```

数学要点：phase_map 是 {0,1,2} 的置换且三通道电流和为零，故 `−ch[map_a]−ch[map_b] = ch[map_c]` 恒成立，第三通道重构公式无需改动。每通道各自的零偏/符号（S1a 绑定的**通道**属性）保持绑定在通道上，随通道被路由——这正是对称性的含义。

**行为兼容**：perm0（恒等）下输出与历史逐字节一致；S0–S4 零影响。快路径仅增加两次比较/查表，相对每次 ~十几拍的软浮点 Clarke/Park 可忽略。

### 3.2 命名矫正（防复发）

| 旧（phase 冒名） | 新（channel 正名） | 位置 |
| --- | --- | --- |
| `foc_raw_current_sample_t.phase_a_raw/phase_b_raw` | `channel_u_raw/channel_v_raw` | foc_types.h |
| `foc_current_calibration_t.phase_a/b_zero_raw、phase_a/b_sign` | `channel_u/v_zero_raw、channel_u/v_sign` | foc_types.h（6 文件 14 处引用同步） |

契约注释更新：
- `foc_phase_map_t`：写明"**必须对称应用在两个适配点**（PWM 输出 + ADC 电流输入），只应用一侧 = 电流环反馈错位"；
- `foc_current_model.h/.c`：计算链路补"按 phase_map 路由到逻辑相"一步；
- S1a 两处绑定注释补"sign_u/v 是通道符号，与 phase_map 无关"；
- `foc_runtime.c` 输出侧重排注释加对称性契约引用。
